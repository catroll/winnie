# Brand mark and app icons

The one drawing behind the Android launcher icon and the console's tab icon,
and the rules that keep the two in step.

## The mark

The woodpecker comes from the separate logo project
(`WLB/projects/woodpecker-logo`, v6) and is vendored verbatim at
[`tools/brand/woodpecker-logo.svg`](../tools/brand/woodpecker-logo.svg). It is a
single even-odd path: the frame circle, the bird and the eye share one fill, and
the white areas are holes. Nothing in the icon pipeline redraws it — the script
only puts a disc behind it and changes the fill.

Its frame geometry is taken from that project's frozen `fitted.json` rather than
re-measured, so the mark keeps its own off-centre composition: centre
`(299.552, 299.783)`, outer radius `226.8536`, inner radius `223.1854` in the
source's 600-unit box.

## Why the frame becomes a disc

The frame is a hairline: 3.7 units of 600, 0.62% of the mark's width. At 48 dp
that is 0.3 dp, so an icon drawn with the hairline reads as a bird floating with
no container. Filling the frame's circle replaces the hairline with an edge that
survives 16–48 dp and keeps both the composition (a bird inscribed in a circle)
and the mark's polarity (a dark bird on a light ground).

Two surfaces share that drawing:

| Surface | Drawing |
|---|---|
| Console (tab, sidebar) | A paper disc with the mark on it. On a light page the disc disappears and what is left is the mark exactly as drawn; on a dark page the disc reads as a light badge. One file, no theme variants. |
| Android launcher | The same disc on a navy field, so the icon holds on any wallpaper. |

## Palette

| Token | Value | Use |
|---|---|---|
| Ink | `#003087` | The mark, and the launcher field |
| Paper | `#FFFFFF` | The disc |
| Crimson | `#C8102E` | Review variant only — see "Rejected" |

The logo project's v6 pairs that navy with crimson. The icons use navy and paper
only, so the app icon, the tab icon and the sidebar brand read as one family.

## Assets

Generated by `tools/brand/build.py`; edit the script, not these files.

| File | Role |
|---|---|
| `apps/android/.../mipmap-anydpi-v26/ic_launcher.xml` | Adaptive icon: background colour, foreground, monochrome layer |
| `apps/android/.../mipmap-anydpi-v26/ic_launcher_round.xml` | Same, for `android:roundIcon` |
| `apps/android/.../drawable/ic_launcher_foreground.xml` | Paper disc r = 31 dp plus the navy mark, inside the 66 dp safe zone |
| `apps/android/.../drawable/ic_launcher_monochrome.xml` | The bird alone, 52 dp tall, centred, frame clipped away |
| `apps/android/.../values/colors.xml` | `ic_launcher_background` |
| `apps/admin/public/favicon.svg` | Browser tab, 2% frame padding |
| `apps/admin/public/logo.svg` | Sidebar brand, 6% frame padding |
| `apps/admin/public/apple-touch-icon.png` | iOS home screen, 180 px, full-bleed navy |

`<monochrome>` sits in the `v26` file rather than a `v33` one: the platform
ignores an unknown child of `<adaptive-icon>` with a warning, which is why
Google's own templates ship it that way. A second file would have to duplicate
both layers.

There are no legacy PNG mipmaps. `minSdk = 26` means an adaptive icon is always
available, so a `mipmap-{mdpi..xxxhdpi}` set would only be dead weight.

## Android geometry

The adaptive canvas is 108 dp, of which the launcher shows the middle 72 dp and
guarantees the middle 66 dp. The disc at 31 dp fills 86% of the visible width and
leaves a 5 dp field margin; 33 dp (the safe radius) was rejected because on a
circular mask the paper disc then sits on the mask edge itself.

The themed-icon layer drops the disc and the frame, because the system supplies
the container and tints a single colour. Its bird is centred on the bird's own
bounding box rather than on the frame: inside the mark the bird sits 35.6 units
(the frame's radius is 226.9) low and slightly left, which is right when it sits
in the badge and wrong when the container belongs to the launcher.

Both vector drawables carry pre-transformed path data. A `VectorDrawable` has no
transform on a path, and a `<group>` scale plus a `<clip-path>` would put the
clip in the group's coordinate space — see
[LESSONS-android.md](./LESSONS-android.md). Baking the numbers also means the
compiled drawable is the geometry that was reviewed.

## Regenerating

```bash
python3 tools/brand/build.py            # admin + Android + touch icon
python3 tools/brand/build.py --sheet    # add review sheets in .tmp/brand/
```

The touch icon needs a real browser, because `rsvg-convert` is not installed and
ImageMagick's fallback renderer drops strokes. Point `FIREFOX_BIN` at a Firefox
binary if the default snap path does not exist; the script asserts the PNG comes
out 180×180. Review sheets are SVG and are meant to be screenshotted with the
same browser at the sizes listed on them.

After regenerating, rebuild the APK and run the Android unit tests:
`LauncherIconTest` rasterises both drawables and asserts the disc, the mask and
the clipped frame, so a bad regeneration fails there instead of on a home screen.

## Reviewing an icon

Review at the size the launcher shows, not the size the canvas is. A 108 dp
square preview overstates every margin by 1.5×; the adaptive icon draws its art
at 1.5× the bounds and crops to the middle 72 dp. Both common mask shapes are
worth checking, because a disc that is comfortable inside a circle can look
cramped inside a squircle.

## Rejected

- **v6's crimson disc on navy, with the black hairline between them.** At 48 dp
  the hairline is 0.3 dp: it turns two saturated colours into a smudge instead of
  an edge. The crimson is kept in the review sheet as a variant, not shipped.
- **The white bird knocked out of the navy field, no disc.** Boldest at 144 px,
  but the circle disappears into the launcher mask and the eye and crest gap fill
  in at 32 px, so the two things that make it a woodpecker are the first to go.
- **A navy disc on paper.** The disc has to fill 92% of the visible width to keep
  the bird legible, which puts it on the mask edge; the icon then reads as a
  solid navy tile on a circular mask and as a circle-in-a-square on a squircle.
- **Recolouring the bird white on crimson** for a stronger accent. It inverts the
  mark's polarity and no longer matches the console's badge.
