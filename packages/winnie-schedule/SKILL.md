# WLB 周程

日程的唯一事实来源是 WLB 仓库 `~/Projects/Mine/WLB/work/` 下的 Markdown：**一周一个文件，一天一个
`###` 小节，一件事一行 checkbox**。复杂内容不写进周文件，另开 `.md` 或目录，用链接挂回当天那一行。

改日程优先用 `winnie-schedule`（下一节），它只改目标行、其余字节不动；手改文件也可以，但必须遵守
本文的格式，否则解析工具读不到那一行。

## 一、目录与文件

```
WLB/work/<YYYY>/Q<季度>/<MM>/<YYYYMM>-<DD>-<DD>.md
                        │        │      │     └─ 周日（两位）
                        │        │      └─ 周一（两位）
                        │        └─ 周一所在的年月，例：202610
                        └─ 周一所在月份，季度按它算：(MM+2)//3
```

- 例：2026-10-05 ~ 10-11 → `work/2026/Q4/10/202610-05-11.md`。
- 跨月的周按**周一**归位：2026-10-26 ~ 11-01 → `work/2026/Q4/10/202610-26-01.md`（在 `10/`，不在 `11/`）。
- **2022 年及以前没有季度目录**：`work/2019/04/201904-01-07.md`。只读时两种布局都要认。
- 周期软链接在仓库根：`S_CURRENT` → 本月目录、`S_LAST` → 上月、`S_NEXT` → 下月。
  写文件时用真实路径，不要写进软链接名。
- 月份目录里的 `_weekly.md` 是指向**本周**文件的软链接，由每周生成脚本维护，不要手改。
- 周编号（A-E，按当月第几个周一）：`2026-10A` = 2026-10-05 那周。出现在 `-weekly.md` 标题和
  `TODO.md` 的会议小节里。

### 一周的伴随文件

| 文件 | 内容 | 谁生成 |
| --- | --- | --- |
| `<YYYYMM>-<DD>-<DD>.md` | 周程本体（本文主角） | `tools/weekly.py` |
| `<YYYYMM>-<DD>-<DD>-weekly.md` | 周会纪要（值班问题/工作回顾/下周安排） | `tools/weekly.py` |
| `<YYYYMMDD>-report.md`（周日日期） | 工作汇报 | `tools/weekly.py` |
| `YYYYMMDD-<slug>.md` | 当天某件事的排查记录/报告 | 手写，命名规则见 skill `wlb-work-notes` |
| `YYYYMMDD-<slug>/` | 一件事的附件目录（脚本、原始日志、配置快照） | 手写 |
| `README.md` / `TODO.md` / `REVIEW.md` | 月/季/年的索引与待办 | `tools/weekly.py` |

**新建周文件不是本工具的事**：周文件的骨架（含例行事项、徽章定义）由 WLB `tools/weekly.py`
生成，它一次补齐本月、本周和未来三周。缺失时先跑它，再用本工具加事项。

## 二、周文件结构

```markdown
# 周安排 05 - 11

```txt
+----+----+----+----+----+----+----+
| 一 | 二 | 三 | 四 | 五 | 六 | 日 |
+----+----+----+----+----+----+----+
|  5 |  6 |  7 |  8 |  9 | 10 | 11 |
+----+----+----+----+----+----+----+
```

## 工作事项                     ← 周级事项，不带日期

- [ ] **`项目名称`** 开发内容描述
- [ ] 季度目标对齐全组

### 10/05 周一                 ← 日分区，一周七个

- [ ] `10/05` [周一] [09:30~10:30] WoodyCoder 测试报告分析，发出邮件简报
- [x] `10/05` 已完成的事
    - 缩进的行属于上一行，不是新事项

## 周末总结                     ← 散文区，没有事项

### 本周工作总结               ← 这里的列表项不是事项

... 值班事项，开发事项，遇到的问题

<!-- ############################################################ -->

[重点]: https://img.shields.io/badge/-⏺-red "重点"   ← 徽章定义，别动
```

规则：

- 一级标题 `# 周安排 <周一> - <周日>`；日历块是纯展示，**不手工改**。
- `## 工作事项` 放跨天/项目级事项，**不带 `` `MM/DD` `` 标签**。
- `## 周末总结` 及其 `###` 子节是写总结的地方，里面的列表项不算事项。
- 文件末尾的链接定义（`[重点]:`、`[status:done]:`、`[type:feat]:` 等）是徽章字典，增删事项时不要移动或删除。

## 三、事项行语法

```
- [ ] `10/05` [每天] [周一] [09:30~10:30] [newapi] 事项正文
  │    │       │      │      │             │        └─ 正文
  │    │       │      │      │             └─ 额外标签（项目名等，可省略）
  │    │       │      │      └─ 时间，HH:MM~HH:MM；只有起点时写 [14:00]
  │    │       │      └─ 星期，跨天复盘用；与所在小节一致
  │    │       └─ 每天固定事项（值班巡检等）
  │    └─ 日期，等于所在小节；周级事项没有这一段
  └─ 复选框：[ ] 未完成，[x] 已完成
```

- 标签顺序固定为：日期 → `[每天]` → `[周X]` → 时间 → 其他标签。工具会按这个顺序重排。
- 前缀之后空一格接正文；正文里可以放 `**加粗**`、`` `代码` ``、`@人`。
- 缩进 4~6 空格的续行、子列表、代码块都属于上一条事项；子列表里的 checkbox 不是独立事项。
- 这一段缩进内容就是该事项的正文，按 Markdown 理解：解析结果是每条事项的 `note` 字段，公共缩进
  已经去掉（4 个前导空格在 Markdown 里是代码块，不去掉整段会渲染成等宽代码）。`show`/`list` 会把它
  打印在事项下面，`--no-note` 关掉；`parse --json` 里每条都有 `note`，控制台日程卡片按 Markdown 渲染。
- 正文里行与行之间就是换行；要分段、或让 `1.`/`-` 变成真正的列表，**空一行**再写下一段。
- 时间区间用 `~`（`[09:30~10:30]`），历史文件里也有 `-`，解析都认，写出统一用 `~`。
- 旧格式（2019-2023）：没有 `### MM/DD` 日分区，事项写成 `- [ ] **04/01** 正文`。这类文件**只读**。

## 四、复杂内容放外面

一条事项写不完时，不要往事项行里堆：在**同一个月目录**建文件或目录，再在事项行末尾链接。

```markdown
- [ ] `10/08` hub 平台网络问题排查，参考：
    - [hub 首字节实测 —— 晚高峰](20261008-hub-shanedit-com-latency-peak.md)
    - <20261008-hub-shanedit-com-network-problem.md>
    - [脚本](network_diag.sh)
```

- 链接写法：`[描述](相对文件名)` 或尖括号 `<相对文件名>`，路径相对周文件所在目录。
- 文件命名、`-report` 后缀、域名转连字符等规则见 skill `wlb-work-notes`，不要另起一套。
- 同一天同一主题再写一次时**改原文件**，不要建 `-v2`、`-final`。

## 五、用工具读写

所有命令都通过日期定位周文件，不需要路径。日期可写 `today` / `tomorrow` / `yesterday` /
`+3d` / `-1w` / `YYYY-MM-DD` / `YYYYMMDD` / `MM/DD`。

```bash
WS=~/Projects/Mine/winnie/packages/winnie-schedule
sc() { PYTHONPATH="$WS/src" python3 -m winnie_schedule --root ~/Projects/Mine/WLB "$@"; }
```

| 目的 | 命令 |
| --- | --- |
| 看本周 | `sc show today` |
| 看某天 | `sc show 2026-10-05 --day` |
| 只看没做的 | `sc list today --pending` |
| 机器可读 | `sc parse 2026-10-05 --no-lines` |
| 只看标题、不带正文 | `sc list today --no-note` |
| 加事项 | `sc add 2026-10-07 "评审邮件模板" --time 14:00~15:00 --weekday` |
| 加带标签的 | `sc add 2026-10-07 "补 IPv6 健康检查" --tag newapi --done` |
| 加到周级清单 | `sc add 2026-10-05 "完成 Q4 文档迁移" --week-scope` |
| 插到某条之后 | `sc add 2026-10-07 "紧随其后" --after 202610-05-11#10/07#1` |
| 勾完成 | `sc update 202610-05-11#10/05#2 --done` |
| 改时间 | `sc update 202610-05-11#10/05#1 --time 10:00~11:00` |
| 改文字 | `sc update 202610-05-11#10/05#1 --text "新的描述"` |
| 补一段说明 | `sc update 202610-05-11#10/06#1 --note $'第一行\n第二行'` |
| 挪到别的天 | `sc update 202610-05-11#10/07#1 --move 10/09` |
| 按文字改（唯一命中） | `sc update --week 2026-10-05 --match "ip2region" --done` |
| 删事项 | `sc delete 202610-05-11#10/11#1` |
| 按文字删 | `sc delete --week 2026-10-05 --match "临时事项"` |
| 先看 diff 再动手 | 任意增删改命令加 `--dry-run` |

要点：

- **id 是位置编号**：`<周文件 stem>#<MM/DD>#<当天第几条>`，周级事项是 `#week#<第几条>`。
  增删之后同一天后面的编号会顺移，所以改完重新 `list` 取新 id，或者用 `--match`。
- 多行内容用 bash 的 `$'...\n...'` 传真实换行（`"--note a\nb"` 传进去的是字面反斜杠）。
- 拿不准就 `--dry-run`：只打印 unified diff，不落盘。
- 退出码：`0` 成功，`1` 用法/解析错误，`2` 找不到事项或日期，`3` `--match` 命中多条，`4` 只读文件。
- `--json` 用于脚本：`parse` 输出整个周的结构（含每条的 `links`，外链文件一目了然），
  增删改输出 `{changed, diff, event}`。
- 工具只重建被改的那一行，续行、总结、徽章定义原样保留；写盘用临时文件 + `os.replace`，不会写坏半截。

## 六、手改时的红线

1. 只加在对应日期的 `### MM/DD 周X` 小节里；不要塞进 `## 工作事项`（除非确实是周级事项）。
2. 新事项追加在该小节末尾，保持日期递增；不要重排已有事项。
3. 只勾 `[ ]`→`[x]`，不要为了"整理"删掉未完成的旧事项——它们可能还要回顾。
4. 不改日历块、不改文件末尾的徽章定义、不改 `# 周安排` 标题。
5. 不新建 `-v2` / `-final` / `副本`；同一件事就改原文件。
6. 不写密钥、token、密码；需要时写"见 `<文件>`"。
7. 2024 年以前的周文件（无日分区）只读；要补记就在当前周期新建笔记文件。

## 七、检查清单

改完日程过一遍：

1. `sc list <日期> --day` 能看到这一条吗？
2. 日期标签、小节标题、真实星期三者一致吗？（工具会 warn 不一致）
3. 完成的事是不是已经 `[x]`？
4. 长篇内容是不是外链到 `YYYYMMDD-<slug>.md` 而不是塞进事项行？
5. `git -C ~/Projects/Mine/WLB status` 里只有预期的周文件变化吗？
